# Continue Watching: проверка протокола 17 ноября 2026

## Установлено по исходникам

Сам факт, что эфир ещё идёт, не означает отдельный тип списка. Twitch может уже
создавать его архив: `stream.archiveVideo.id` существует со статусом `RECORDING`.
Сохранённая позиция относится к этому ID видео, а не к ID живого broadcast.
В публичной проверке трёх активных эфиров два имели такой архив, один — `null`.
Отсутствующий архив нельзя заменять выдуманным VOD ID.

В сохранённом официальном TV-бандле `tv-app.js` hook `useUpdateUserViewedVideo`
передаёт `stream.archiveVideo.id` (либо ID выбранного VOD), `videoType: VOD` и
позицию. Для live позиция вычисляется по `stream.createdAt`; само обновление
вызывается после последовательного воспроизведения. Это отдельный механизм от
аналитики минут и получения баллов. Он не доказывает зачёт стрика/итогов года.

В Twitch Classic 0.22 `ClassicVodSync` запускается только для VOD. Live-сервис
`PlayChannelPoints` отправляет аналитику/обрабатывает бонусы, но не сохраняет
live-bookmark через archiveVideo. Поэтому отсутствие этой части подтверждено
кодом. Оно не объясняет автоматически, почему импорт списка с телефона пуст.

## Мобильные запросы

Исследован `assets/index.android.bundle` (Hermes v98) из публичного
[ReTwitch 0.5.38-beta](https://github.com/reyohoho/ReTwitch-src/releases/tag/v0.5.38-beta).
APK не запускался. ZIP central directory и нужные entries читались HTTP Range;
для анализа не требовалась установка APK. Строки декодированы hermes-dec 0.1.8.
Инструмент предупреждает о неполной поддержке новых инструкций v98: здесь
использовались декодированные литералы запросов, а не вывод декомпилятора о
поведении всего приложения. Это исследование бандла модифицированной сборки,
не независимая проверка подписи исходного APK Twitch.

В бандле имеются разные поверхности Continue Watching:

- `MwebFollowingTabSections` (ряд подписок): `user.viewedVideos(first: 5)`;
  карточки выбирают `node.self.viewingHistory.position`. У операции также есть
  другие поля/контекст рекомендаций; они не нужны для сокращённой проверки
  самого списка. Нельзя назвать этот ряд любым блоком главной страницы без
  проверки того, какой экран открыт у пользователя.
- `ContinueWatchingFeedVod` (элемент ленты):
  `currentUser.viewedVideos(first: 1, sort: RECOMMENDED)`; позиция выбирается из
  `edges.history.position`. Это не доказательство, что весь ряд подписок
  использует RECOMMENDED: у его запроса такого аргумента нет.
- Нативный DEX содержит `ResumeWatchingVideosQuery` с `viewedVideos(first: $limit)`
  и моделью с limit=10; выбираются `history.position/updatedAt` и VOD-фрагмент,
  включая `self.viewingHistory`. Полный извлечённый запрос также проверялся.

Существующий React Native-перехватчик ReTwitch подтверждает связь мобильного ряда
с полем viewedVideos:
[RnFollowingHook.java](https://github.com/reyohoho/ReTwitch-src/blob/1a754e5a080fa96b47df9a807d61ae85e4512c32/kitchen/mod/src/tv/retwitch/mod/RnFollowingHook.java).

В актуальном официальном web-chunk
[47799-2487798ce4d69421ec71.js](https://assets.twitch.tv/assets/47799-2487798ce4d69421ec71.js)
операция `FollowedStreamsContinueWatching` выбирает `currentUser.viewedVideos`
с limit=20 и excludeHiddenChannels=true. UI отбирает недавние незаконченные
просмотры. Это ещё одна поверхность того же поля, не полный архив просмотров.

## Проверка с разрешённым временным входом

Владелец явно разрешил временный вход на официальном activate-сайте. Использован
зарегистрированный Smart TV client с единственным запрошенным правом
`user:read:follows`; validate подтвердил клиента, право и текущего пользователя.
Владелец отдельно подтвердил, что это тот же аккаунт, что на телефоне. Пароль
не передавался. Сохранение/обнуление позиций, запуск видео, сообщения, трата баллов
и изменение подписок в ходе проверки не выполнялись.

Подтверждена следующая развилка:

1. Запрос 0.22, сокращённый мобильный ряд на пять, мобильная рекомендованная
   выборка и полный нативный запрос возвращают пустые viewedVideos.edges при
   HTTP 200 без GraphQL-ошибок. Простая замена лимита не доказала исправление.
2. Замена публичного Client-ID в запросе при том же выданном grant не изменила
   пустой результат. Это не проверка полноценного входа от другого клиента.
   Выдача device-code мобильному клиенту недоступна (`invalid client`); обхода
   этого ограничения не предпринималось.
3. При чтении доступного каталога `currentUser.followedVideos` у отдельных
   `node.self.viewingHistory` есть ненулевые серверные позиции, в том числе
   для ещё записывающихся архивов. Это серверные отметки аккаунта, не локальная
   история Twitch Classic и не предположение по названию канала.
4. Точный запрос `ClassicVodSyncRead` из 0.22 для одной такой записи также
   возвращает ненулевую позицию, совпадающую с независимым чтением, при пустом
   общем индексе viewedVideos. Следовательно, доступ к самим позициям имеется;
   отдельно не работает перечисление через этот индекс.

Имена аккаунта, ID/названия просмотренных видео, личные позиции, время просмотра,
ответы с приватной историей и временный grant не входят в этот документ/репозиторий.
Личные примеры были показаны только владельцу для сравнения с телефоном.
По завершении проверки временный access token отозван через официальный
revoke endpoint; последующая validate вернула 401. Временные credentials и
ответы с личной историей удалены из рабочей папки диагностики.

## Практическое исправление и пределы

При пустом индексе можно читать серверные позиции у доступных кандидатов:
пагинируемого каталога записей подписок и уже известных клиенту VOD. Незаконченные
кандидаты с ненулевой self.viewingHistory образуют резервный ряд; RECORDING
архивы сохраняются. При открытии позиции перечитываются, а live-запись должна
использовать правильный archiveVideo ID. Визуальные часы просмотра не являются
позицией внутри эфира и не должны подставляться вместо неё.

Такой резервный поиск не равен полной истории аккаунта: он может пропустить
неизвестные клиенту записи неподписанных каналов. Нельзя выдавать каталог подписок
за историю, показывать в продолжении все его записи без положительной серверной
отметки или обещать полное совпадение с мобильным приложением. Пагинация каталога
кандидатов должна быть ограничена и не блокировать показ эфиров/управление.

Точная внутренняя причина пустого индекса Twitch (включая возможную особенность
доступа/индекса/кэша мобильного клиента) ответами сервера не установлена. Нельзя
объявлять её доказанным scope-блоком, поломкой Twitch или локальным кэшем телефона.
Исследование установило рабочий путь к сохранённым позициям и место расхождения.
