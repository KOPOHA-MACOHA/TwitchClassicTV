# Релизы и обновления Twitch Classic

## Что настроено

- `Source checks` проверяет исходники через браузерные сценарии на push / pull request.
- `Build signed APK` собирает и публикует релиз при теге `v0.12` (номер берётся из `fork-build/version.json`) или ручном запуске.
- Приложение запрашивает `https://api.github.com/repos/KOPOHA-MACOHA/TwitchClassicTV/releases/latest` и принимает APK только из Releases этого репозитория с ожидаемым именем. Токен Twitch туда не отправляется. Автопроверка ограничена одним запросом за шесть часов; ручная проверка выполняется сразу.
- APK устанавливается через существующий системный установщик Android с подтверждением пользователя. На ТВ может потребоваться один раз разрешить установку приложений из этого источника.

## Ключ подписи — однократная настройка

Нельзя создавать новый ключ: он не позволит обновить установленную сборку. Приватный ключ текущих сборок хранится отдельно от репозитория. Публичный SHA-256 сертификата:

`95ae6fe54cd368ee2b8826d977edc86f880eb274f8a75fdcfe047e150602149d`

В [Actions secrets](https://github.com/KOPOHA-MACOHA/TwitchClassicTV/settings/secrets/actions) нужно добавить:

| Secret | Значение |
|---|---|
| `CLASSIC_KEYSTORE_BASE64` | Base64 существующего файла keystore, без переносов строк |
| `CLASSIC_KEY_ALIAS` | Alias ключа, по умолчанию `Morphe` |
| `CLASSIC_STORE_PASSWORD` | Пароль хранилища, если задан |
| `CLASSIC_KEY_PASSWORD` | Пароль ключа, если задан |

Ключ нельзя добавлять в git, Issues или публичный артефакт. Workflow восстанавливает его только во временную папку runner и удаляет после сборки. До добавления ключа workflow релиза намеренно завершается с пояснением, а не публикует APK с другой подписью.

Для первых перенесённых сборок доступен `Import existing signed release`: он забирает **уже подписанный локальный APK** по временному адресу из `fork-build/release-import.json`, проверяет SHA-256, исходники, нативный код и сертификат и публикует в Releases. Подписывающий ключ в этом процессе не передаётся.

Если после форка GitHub отключил Actions, включите их на [странице Actions](https://github.com/KOPOHA-MACOHA/TwitchClassicTV/actions). Для публикации workflow имеет `contents: write`.

## Следующая версия

1. Изменить исходники и увеличить `name` / `code` в `fork-build/version.json`. `code` Android должен только расти.
2. Выполнить проверки. `build.py` обновляет `app/general/classic-version.js` из version.json; зафиксировать оба файла.
3. Создать тег, совпадающий с версией: например `v0.13`. Workflow проверяет совпадение номера и подпись, затем создаёт Release с APK, SHA256SUMS и архивом соответствующих исходников.
4. В приложении: Настройки → Дополнительно → обновления. Новые сборки ищутся только в этом форке.

Ключ текущей установки проверен отдельно при локальной сборке. Обычный локальный `build.py` без `--release` годится для разработки, но может создать другую подпись: такую сборку нельзя распространять как обновление существующей установки.
